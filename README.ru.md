# tclwinkit

[English](README.md) · **Русский**

Портативная сборка Tcl 9 для Windows x64 в одном файле.

Один исполняемый файл = целый дистрибутив Tcl 9: интерпретатор (плюс Tk в
GUI-сборках), бинарные расширения, статически влинкованные в exe, и ~700
pure-Tcl библиотек, прицепленных к exe ZIP-архивом, который встроенный
**zipfs** монтирует при старте. Никаких DLL рядом с exe, никакого
установщика, никаких записей в реестр — скопировал один файл и работаешь.

## Скачать

Выберите исполняемый файл в [последнем релизе](https://github.com/nektomk/tclwinkit/releases/latest).
Все четыре несут один и тот же набор — тулчейн это вопрос вкуса, а не качества:

| Файл | Тулчейн | Для чего |
|---|---|---|
| `tclwinkit-…-msvc-x64-console.exe` | MSVC, static CRT | скрипты, замена `tclsh`, REPL |
| `tclwinkit-…-msvc-x64-gui.exe` | MSVC, static CRT | приложения на Tk (замена `wish`) |
| `tclwinkit-…-mingw-x64-console.exe` | MinGW-w64, UCRT | то же, сборка GCC |
| `tclwinkit-…-mingw-x64-gui.exe` | MinGW-w64, UCRT | то же, сборка GCC |
| `tclwinkit-docs-….zip` | — | справочные страницы, HTML-документация, демо, лицензии |

Два независимых тулчейна собирают один и тот же кит, поэтому проблема
тулчейна никогда не становится проблемой дистрибутива. К каждому релизу
прилагается `SHA256SUMS.txt`:

```
certutil -hashfile tclwinkit-….exe SHA256
sha256sum -c SHA256SUMS.txt          # на любой машине с coreutils
```

Суммы можно сверить и со своей сборкой: две полные пересборки на эталонной
машине дают все пять файлов байт-в-байт. См.
[`BUILDING.md`](BUILDING.md) и [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Быстрый старт

```tcl
tclwinkit-….exe script.tcl arg1      ;# как tclsh: запустить скрипт
tclwinkit-….exe                      ;# интерактивный REPL с историей
winkitwish-….exe app.tcl             ;# как wish: приложение на Tk
```

На этом всё. Клавиши REPL и файлы — в разделе «Интерактивный REPL».

## Что внутри

Один файл, при старте — `//zipfs:/app`: ядро Tcl 9, Tk 9 (в GUI-сборках) и
пакеты, каждый из которых здесь за дело:

- **tcllib, tklib** — стандартные библиотеки: JSON, XML, HTML, http, uri,
  base64, структуры, математика, физика, units и сотни других.
- **TWAPI** — Windows API как команды Tcl: процессы, службы, реестр,
  файловая система, COM, управление окнами и вводом. Собственный REPL кита и
  работа с треем/курсорами построены на нём.
- **tdbc + sqlite3** — `tdbc::sqlite3` из коробки, `tdbc::odbc` для всего,
  под что есть ODBC-драйвер.
- **Img** — 19 форматов изображений (PNG, JPEG, TIFF, GIF, BMP, …) для Tk.
- **tkdnd, Treectrl, Itcl, Itk, Iwidgets** — drag-and-drop, деревья,
  объектно-ориентированный Tcl и большой набор виджетов над Itk.
- **TclReadLine** — редактирование строки и дополнение в REPL.
- **mpexpr, rl_json** — математика и JSON на нативной скорости.
- **CAWT** — управление Microsoft Office (Excel, Word, PowerPoint, Outlook)
  через COM.

Отбор пакетов держит образ компактным, и каждый хотя бы раз прогоняется
тестовым набором перед релизом; `package names` в GUI-ките сообщает ~700
имён. Точный список версий всех компонентов — `VERSIONS.txt` в
[docs-архиве](src/docs/README.md); работающий кит сообщает свою версию как
`$::winkit::version`.

## Зачем

Обычные способы получить Tcl 9 на Windows — установщик, пакетный менеджер
или собственная сборка. `tclwinkit` — это **файл, который можно положить в
`PATH`, на USB-флешку или в кэш CI**: интерпретатор и его пакеты
путешествуют вместе.

Типичные случаи: доставить Tcl-приложение на машину, где нельзя ничего
устанавливать; одноразовая среда для скриптов в Windows-контейнере или на
заблокированном десктопе; запустить чужой Tcl 8/9 скрипт, не трогая
системный Tcl.

Переносимость в строгом смысле: все четыре exe зависят только от системных
DLL Windows, и запуск из read-only каталога работает — при старте ничего не
пишется рядом с exe, так что защищённая от записи USB-флешка подходит.

## Интерактивный REPL

Консольный кит — не голый `tclsh`: он запускает REPL с редактированием
строки, историей и дополнением, реализованный на чистом Tcl поверх
Win32-shim на TWAPI. Ввод символов — через `ReadConsoleInput`, отрисовка —
через virtual terminal processing (Windows 10+).

| Клавиша | Действие |
|---|---|
| Up / Down | история |
| Left / Right, Home / End, Del | редактирование строки |
| Ctrl-A/E/K/U/W, Ctrl-P/N | emacs-шорткаты |
| Ctrl-C | очистить текущую строку (в режиме ввода) |
| Shift-Tab | дополнение (команды, переменные, файлы) |
| Ctrl-T | вкл/выкл дополнение по простому Tab |
| Ctrl-D (на пустой строке), `exit` | выход (история сохраняется) |

История: `~/.tclline_history`, конфиг REPL: `~/.tcllinerc`, rc-файл кита
(аналог tclshrc): `~/winkitrc.tcl` или `~/winkitwishrc.tcl`.

## Архив с документацией

Архив с документацией — пятый ассет релиза, потому что киты несут **только
рантайм**. Внутри: `man/`, `html/`, `demos/`, `docs/`, `tools/` (рендерер
ман без groff и обёртка для iwidgets-демо), `LICENSES/`, `LICENSE`,
`THIRD-PARTY-NOTICES.md`, `VERSIONS.txt`, `MANIFEST.txt`. Распаковав архив
рядом с китом, демо запускаются тем же exe:

```
winkitwish-….exe demos\tk\widget           # браузер виджетов Tk
winkitwish-….exe demos\iwidgets\catalog    # каталог iwidgets
tclwinkit-….exe  tools\man.tcl man\tcl\subst.n
```

Полный состав архива — в [`src/docs/README.md`](src/docs/README.md) (сверху
английская часть, ниже подробная русская).

## Чем это не является

Спрашивают достаточно часто, чтобы ответить до трекера:

- **Не форк Tcl.** Tcl, Tk и каждый бандл-пакет — апстримные релизы,
  немодифицированные, кроме мест, указанных в [`patches/`](patches/README.md).
- **Не `tclkit`.** tclkit — рантайм под экосистему Starpack/VFS, со своим
  пакетом `filesystem` и своим графиком релизов. Здесь нет ни формата
  `.kit`, ни `sdx`, ни шелла.
- **Не starpack.** Ничего не самораспаковывается; ничего не пишется во
  временный каталог при старте. Архив читается на месте, через
  смонтированную файловую систему.
- **Не установщик и не менеджер.** Не регистрирует ассоциации файлов, не
  трогает `PATH`, не сосуществует с системным Tcl — это просто
  интерпретатор, на который вы указали.
- **Не ActiveState ActiveTcl.** Ни проприетарной сборки, ни `teapot`, ни
  закрытых инструментов; каждый байт — либо апстримный open source, либо
  наша обвязка под MIT.

## Известные ограничения

- **`tdbc::mysql` и `tdbc::postgres` отсутствуют** — им нужны вендорные
  SDK, которые здесь не распространяются. `tdbc::sqlite3` и `tdbc::odbc`
  включены.
- **TWAPI протестирован частично.** Его собственный набор даёт отказы на
  этой машине (в Windows больше нет `wmic`, COM-объект `Twapi.Test` не
  зарегистрирован, часть наборов рассчитана на интерактивные диалоги,
  группа наборов старая — crypto, pdh, ui, tls). Функции, которые
  использует кит, покрыты собственными тестами кита; подробный разбор — в
  [`docs/NOTES.md`](docs/NOTES.md).
- **Вендорные тестовые наборы прогнаны, их отказы классифицированы, а не
  скрыты** — числа и причины в [`docs/NOTES.md`](docs/NOTES.md).
