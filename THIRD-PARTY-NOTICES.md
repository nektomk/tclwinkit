# Third-party notices

tclwinkit bundles third-party software inside its single-file executables.
This file is the required attribution document: it names every bundled
component, its license, its copyright holders, and — where the license says
so — reproduces the notice text that must accompany a redistribution.

Verbatim license texts live in [`LICENSES/`](LICENSES/). Every file in that
directory is generated from the vendor sources by
[`scripts/make-licenses.ps1`](scripts/make-licenses.ps1); nothing there is
hand-typed, and `make-licenses.ps1 -Check` verifies the tree against the
sources. This file quotes only the passages the respective licenses require to
be reproduced in documentation, plus components whose notice exists **only**
inside source headers.

## How the kit is put together

Two build flavors, four executables:

| flavor | console | GUI | C runtime |
|---|---|---|---|
| MSVC (Visual Studio Build Tools, x64) | `tclwinkit-msvc-x64-console.exe` | `tclwinkit-msvc-x64-gui.exe` | static |
| MinGW-w64 (MSYS2 ucrt64, x64) | `tclwinkit-mingw-x64-console.exe` | `tclwinkit-mingw-x64-gui.exe` | static |

Each executable carries three layers:

1. **Statically linked C code** — Tcl/Tk core, in-tree `compat/` libraries,
   Tcl/Tk extensions, image codec libraries. Their object code is inside the
   `.exe`, and these are the licenses that most often require attribution in
   documentation, so they are listed first and in most detail.
2. **Pure-Tcl sources in the `kit.vfs` zip layer** — extension package glue
   plus the tcllib/tklib/iwidgets/CAWT/TclReadLine collections.
3. **Our own runtime glue** — [`src/kit/`](src/kit), MIT, see
   [`LICENSE`](LICENSE).

Both flavors ship byte-identical license texts (verified by SHA256 across the
`build/msvc` and `build/mingw` trees), so one notice set covers both.

### Modifications and pruning

We modify vendor sources. Every modification is listed in
[`patches/README.md`](patches/README.md) with the file, the reason and the
`WINKIT:` marker used in the code; copyright headers of modified files are
never removed. For the Tcl-family licenses, which require that modified files
indicate their new terms, those marker lines serve that purpose.

The staging step also **prunes** vendor trees: documentation, tests, headers,
makefiles and build scaffolding do not ship. Pruning removes files, never
clauses — where a pruned file was itself a required notice, that notice is
reproduced below and stored under [`LICENSES/`](LICENSES/). Section 7 lists
what is not shipped.

[`LICENSES/kit-headers/`](LICENSES/kit-headers/) contains the mechanical
full audit of every Tcl/Itcl/Itk source that actually ships in the kit
(687 tcllib + 237 tklib + 58 iwidgets files, every comment run of every file
examined), so the absence of a notice next to a shipped file can be told apart
from an unlicensed file.

### 1.3 Not linked, and therefore not in the executables

Stated explicitly, so that a scanner finding these files in a source tree does
not mistake them for an obligation we missed:

- **Apache-2.0** — `tcl9.0.4/compat/zlib/contrib/minizip/skipset.h` (PCG32,
  M. E. O'Neill) and the rest of minizip (`unzip.c`, `zip.c`, `ioapi.c`,
  `mztools.c`, `iowin32.c`). None compile in either flavor: zero matching
  objects in `tcl_StaticX` (MSVC) or `win/*.o` (MinGW).
- **MySQL Client C API (GPL with FOSS exception), PostgreSQL libpq** —
  `tdbc::mysql` and `tdbc::postgres` are not part of the build: their `.lib`
  files are produced by the MSVC core build but are absent from `PKGLIBS` and
  no `DKIT_HAVE_TDBCMYSQL` / `DKIT_HAVE_TDBCPOSTGRES` is defined; neither is
  built at all by the MinGW flavor. No client library source is vendored.
- **GNU readline (GPL-3)** — deliberately avoided: the REPL is pure Tcl
  ([TclReadLine](#25-tclreadline)), so no readline code is present.
- **`tcl9.0.4/compat/` portability shims** (`fake-rfc2553.c`, `gettod.c`,
  `mkstemp.c`, `strncasecmp.c`, `waitpid.c`, `dlfcn.h`) — not compiled on
  Windows; zero objects in both flavors.
- **GPL v2 code in Img's libpng contrib** (`contrib/gregbook/`, `pngminus`,
  `pngexif`) — example programs, never compiled; no copyleft reaches the
  binaries.
- **`tcllib/json/c/json.tab.c`** (Bison-generated, GPL-2.0+) — pruned; only the
  grammar `json.y` is staged.
- **BSD-4-Clause (original, advertising clause) other than libtiff's LZW
  module** — none.

## 7. Not shipped

Vendor documentation (`*.man`, `*.md`, `*.html`, `doc/`, `demos/`, `tests/`),
C headers and object scaffolding (`*.h`, `*.c`, `*.in`, `Makefile*`,
`configure`, `tclconfig/`, `*.vc`, `*.def`), and packaging metadata are pruned
from `kit.vfs`. Two consequences worth stating:

- Some pruned files were themselves required notices. Those are reproduced
  above and stored under [`LICENSES/`](LICENSES/) — see
  [§2.2](#22-tcllib-20), [§2.3](#23-tklib-09), [§2.6](#26-iwidgets-411).
- Everything else that ships unmodified from a vendor tree ships as upstream
  published it. In particular `tcllib2.0/devtools/` ships with the
  self-signed certificate material (`ca.crt`, `ca.key`, `ca.key.password`,
  `receiver.*`, `transmitter.*`, `recreate-certs`) that is part of the tcllib
  2.0 release: the module's own README states "The code is used in some of the
  tcllib testsuites", and 304 of tcllib's `.test` files reference it. Removing
  or altering files inside another project's release is not ours to do, so the
  material ships as received. It is test fixtures for a test suite that is not
  shipped, and grants no access to anything.

Pruning removes files, never clauses.
