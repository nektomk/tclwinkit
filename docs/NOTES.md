# Инженерные заметки: прогоны вендорских тестовых наборов на китах

Здесь зафиксированы результаты прогонов штатных тестовых наборов пакетов
(`*.test` под tcltest) на собранных китах tclwinkit: что именно измерялось, какие
числа получены, почему происходят падения и что осознанно принято как известное
поведение. Документ существует для того, чтобы эти прогоны не приходилось
повторять: числа ниже — из сборок эпохи 0.1, все замеры сделаны per-file и
агрегированы из сводных строк tcltest каждого файла.

Все прогоны делались на MSVC-китах (`tclwinkit-msvc.exe` — консоль,
`winkitwish-msvc.exe` — GUI); mingw-версии в прогонах участвовали только на
финальном свипе, где цифры обеих цепочек совпали байт-в-байт. Собственно
измерения делятся на два состояния: **до патчей** (диагноз) и **после патчей**
(то, что живёт в релизе). Патчи — в `patches/`, индекс и обоснование каждой
правки — в [`patches/README.md`](../patches/README.md); фикс статики в дочерних
interp и ресурсы курсоров живут в дереве кита (`src/kit/vfs/lib/pkgIndex.tcl`,
`src/kit/kit_register.c`, `src/kit/kit_wish.rc`).

## 1. Как считались числа

- tcltest встроен в кит: `package require tcltest` → **2.5.11** (ветка 2.6 в ките
  недоступна). Агрегат — сумма последних сводных строк `Total/Passed/Skipped/Failed`
  каждого тестового файла.
- GUI-процесс (wish-кит) в консоль не пишет: вывод обязателен через
  перенаправление stdout отдельным потоком, иначе получается 0 байт. Проверено.
- tcltest при загрузке разбирает глобальный `$argv` как собственные флаги
  (`tcltest.tcl:1583 ProcessFlags $::argv`), поэтому в per-file драйвере перед
  `source` файла теста необходимо выполнить `set argv {}`; иначе наблюдается
  «missing value for option <путь>».
- `load {} P <slave>` работает сам по себе: таблица статических библиотек
  (`firstLibraryPtr`, `tclLoad.c`) глобальна на процесс. Падения загрузки в
  дочерних interp были про регистрацию и auto_path, а не про область видимости
  таблицы.
- Имена переменных PowerShell нечувствительны к регистру: счётчики агрегата
  `$T/$P/$S/$F` схлопываются с временными `$t/$p/$s/$f` и дают арифметическую
  ошибку на середине прогона. В раннерах используются раздельные префиксы
  (`$aggT…` и `$nt…`).
- Два класса драйверов непригодны без предзагрузки пакетов: без
  `package require rl_json` сводная строка не появляется («Total 0» по всем
  30 файлам, агрегат выглядит как 0/0/0/0); набор tcllib требует `tcltest 1.0`,
  что под Tcl 9 означает «только 1.x», и обрывается «package tcltest is not
  present», пока tcltest не загружен явно. Без предзагрузки ложно-ошибочными
  выглядят doctools 3/3, textutil 7/10, struct 9/16; с `package require tcltest`
  до теста — всё проходит.
- mpexpr: только `cd` в каталог тестов и `source mpexpr.test` / `mpformat.test`
  в главном interp (статичность детектируется самим файлом теста); Unix-style
  тесты пропускаются. Сводных чисел tcltest не выдаётся, признак успеха —
  завершение без FAILED.
- Tk demos в кит не входят; для прогонов, которым нужна `$tk_library` с
  картинками (например `library/demos/images/flagup.xbm`), применялся fallback
  на демо-дерево из исходников сборки Tk.
- Каталог тестов Treectrl физически лежит в дереве `tktreectrl-2.5.1`, тогда как
  в кит стабируется `lib/treectrl2.5.2/` (см. § 9).

### 4.1 itcl/itk в slave- и safe-interp под статической сборкой

Причины падений `interp-*` (itcl) и `interp.test` (itk), разобранные в исходниках
Tcl 9.0.4. Мотивирующий сценарий: `thread create { package require sqlite3 ;
thread wait }` — в новом interp, созданном потоком, пакет не находился.

1. `package require X` в новом interp падал с «can't find package», потому что все
   `ifneeded` объявлялись программно в `lib/kit_init.tcl` — только в главном
   interp. Механизм ядра другой: `init.tcl` кладёт `[file dirname $tcl_library]`
   (`//zipfs:/app`) в `auto_path` каждого нового interp, а `tclPkgUnknown`
   сканирует детей элементов `auto_path` на `pkgIndex.tcl`, поэтому
   `//zipfs:/app/lib/pkgIndex.tcl` находится автоматически в любом interp.
   Решение: отдельный файл `src/kit/vfs/lib/pkgIndex.tcl` — физический индекс
   всех static/mixed-пакетов (перенесён из `kit_init.tcl` дословно, плюс
   обвязка `auto_path` внутри; всё в namespace `::winkit::pkgindex`, `glob` под
   `catch`, чтобы оставаться безопасным в safe-interp). `kit_init.tcl` стал
   тонким: `::tcl::Pkg::source //zipfs:/app/lib/pkgIndex.tcl`. Оба файла
   копируются assemble-скриптами.
2. Регистр имени библиотеки загрузки: тесты itcl/itk зовут `load "" Itcl` (с
   большой буквы), а зарегистрировано было только `itcl`. Решение: в
   `src/kit/kit_register.c` `Tcl_StaticLibrary(NULL, "Itcl", Itcl_Init,
   Itcl_SafeInit)` дополнительно к `"itcl"`; для rl_json зарегистрирован
   `Rl_json_SafeInit` (он есть в 0.17.8 и делегирует `Init` — у пакета нет
   небезопасной поверхности); для Itk добавлена SafeInit-обёртка
   `ItkKit_SafeInit` (`package require itcl`, игнорируя ошибку, затем
   `Itk_SafeInit` из `itkBase.c`).

### 4.2 X11-имена курсоров: не несовместимость пакетов

`gumby`, `trek`, `top_left_arrow`, `hand1` на Windows — это именованные
CURSOR-ресурсы исполняемого файла (`tkWinCursor.c`:
`LoadCursorA(Tk_GetHINSTANCE(), name)`); стоковый wish получает их из
`win/rc/wish.rc` → `tk_base.rc`. В китах этих ресурсов не было совсем, отсюда
«bad cursor spec» и порядка 50 падений iwidgets плюс 8 у itk. Это дефект staging
кита, а не несовместимость пакетов. Решение: `src/kit/kit_wish.rc`
(`#include tk_base.rc`, `STATIC_BUILD=1`), компилируется `rc`/`windres` и
линкуется в GUI-кит обеими цепочками. После фикса курсоровые имена работают во
всех GUI-китах.

### 4.3 iwidgets 4.1.1: четыре класса падений «до патчей» (236)

- (a) `case` удалён в Tcl 9 — `colors.itcl`, `canvasprintbox.itk`; каскад:
  canvasprintbox 31F + canvasprintdialog 52F + tabnotebook + usual (порядка 85).
- (b) `trace variable` удалён в Tcl 9 — `radiobox.itk:114`,
  `scopedobject.itcl:129` → radiobox 33F; `scopedobject` — базовый класс для
  половины виджетов, поэтому класс давал и большую часть точечных падений.
- (c) X11-имена курсоров, отклоняемые Tk 9.0 на Windows — около 45 файлов по
  1–2 падения плюс каскад messagebox 59F (снят § 4.2, а не патчем пакета).
- (d) Точечные поведенческие, порядка 15: `hierarchy-3.9…3.12`
  (expand/collapse с пустым именем), `extbutton-2.20`, `menubar`, `toolbar` и
  подобные — легаси-ожидания самих тестов относительно сообщений и значений Tk 9.

Вывод: iwidgets 4.1.1 (2008) формально не портирован под Tcl 9 — ломается API
пакета, а не кит. Устранено патчами `patches/iwidgets/{generic,tests}/`:
`case` → `switch --`, `trace variable/vdelete` → `trace add/remove VARIABLE`
(ключевое слово `variable` обязательно, иначе
`bad option "::itcl::internal::variables::…"`; флаги `w`/`u` → `write`/`undef`),
`flash` → явный `return` (Tk 9 оставляет в результате имя
`::tk::icons::indicator16_…` вместо документированной пустой строки), и правки
легаси-ожиданий в семи тестовых файлах (`bad screen distance` → `expected screen
distance but got`, `doesn't exist` → `does not exist`, `-underline -1` → `{}`,
`glob $env(HOME)/*` → прямые слеши через `string map`, `/tmp/…` → временной
каталог Windows с прямыми слешами). Итог: **3308/3308/0F**, 52 файла, 0 файлов
в состоянии ERROR.

## 5. twapi 5.2.0: частичный прогон как итоговое состояние

Процедура: per-file, 34 файла. Результат — Total 3494, Passed 2673, Skipped 441,
Failed 380; три файла в состоянии SOURCE-ERROR (`base`, `security`, `share` —
`wmic` отсутствует уже на этапе `source`), два файла без сводной строки
(`input`, `network` — интерактивные диалоги: «сохранить изменения» в Notepad,
буфер обмена).

Причины падений, основные группы: отсутствие `wmic` (17x), незарегистрированный
COM-тест-объект `Twapi.Test` (20x; нужен апстримовый `comtest`), списки PID
вместо скаляров (`process.test`, около 100x — поведение под множество процессов
и списков), далее `crypto` 67, `pdh` 28, `ui` 30, `tls` 12 и т.п. — среда и
древность тестов, а не дефекты кита.

Статус: задокументировано как частичное. Нужные функции twapi в ките присутствуют;
CAWT, построенный поверх TWAPI, протестирован отдельно и независимо. Углубление
набора осознанно не требуется; после фикса статики в дочерних interp прогон не
перепроверялся, потому что падения twapi с дочерними interp не связаны.

## 6. rl_json `misc-3.2`

Падение `misc-3.2` — единственная неудача набора (2565/2561/3/1): тест создаёт
safe-interp и требует в нём `rl_json`, а в статической сборке
`Rl_json_SafeInit` не был зарегистрирован. В 0.17.8 эта функция существует и
делегирует `Rl_json_Init` (небезопасной поверхности у пакета нет), поэтому
решение — регистрация SafeInit в `src/kit/kit_register.c`. После фикса набор
даёт 2565/2562/3/0. Отдельная особенность пакета: C-команды доступны только в
главном interp, поэтому `package require rl_json` обязателен до `source` тестов.

## 8. Что не гонялось и почему

- **tcllib 2.0 целиком** (~420 файлов) — нестандартная тестовая обвязка
  `devtools/testutilities.tcl`, под Tcl 9 даёт много шума вне дефектов кита.
  Вместо полного набора проверены четыре модуля (тесты брались из неурезанных
  исходников, кит — урезанный; ×2 цепочки, цифры идентичны):
  doctools 599/599/0/0 (3 файла), textutil 211/211/0/0 (10), struct
  2708/2672/36skip/0 (16), json 527/527/0/0 (2).
- **tklib 0.9** (9 файлов) — та же нестандартная обвязка; не гонялся.
- **Tk 9.0.4 core** (115 `.test` + `tests/ttk`) — большой объём, не запускался.
- **cawt** — 0 тестов; набор отсутствует.
- **tkdnd** — набора tcltest нет (§ 4.4), проверено загрузкой шести ручных
  скриптов.
- **Docs-артефакт** (`tclwinkit-docs-<вер>.zip`, пятый артефакт сборки)
  отдельным прогоном не тестируется: он публикует вендорские файлы как есть.
  Часть демо — суб-скрипты общего браузера (`demos/tk/widget`,
  `demos/iwidgets/catalog`, `demos/treectrl/demo.tcl`), прямой запуск которых
  штатно сообщает «этот скрипт надо запускать из …» — это поведение вендора, а не
  дефект архива или кита, поэтому подгонять каждый файл под самостоятельный старт
  не нужно. Разовая проверка запускаемости дала: 220 кандидатов, 219 STARTED,
  1 EXITED-CLEAN (`cawt/RunTest.tcl` требует имя namespace аргументом), 0 FAILED —
  одинаково на msvc и mingw. Office-часть требует установленного Office (COM),
  что задокументировано в README архива; `cawt/TestPrograms` (177 файлов)
  сохранены в архиве как демо автора, потому что `tablelist` в ките есть
  (tklib 7.4.1) и они запускаются.

Отдельно зафиксировано состояние документов: `docs/ENVIRONMENT.md` и
`docs/PLAN.md` цитируют −32,4 МБ / −4276 файлов на GUI-кит и docs-архив
13,49 МБ / 3065 записей с плоским `licenses/`. Актуальные значения: −32,40 МБ /
−4269 файлов на GUI-кит; docs-архив 14 231 971 B / 3129 записей; плоский
`licenses/` заменён генерируемым `LICENSES/` из 54 файлов плюс `LICENSE` и
`THIRD-PARTY-NOTICES.md` в корне архива.

## 9. Версия Treectrl и отложенная правка

Набор тестов, который прогонялся, — из дерева Treectrl **2.5.1**, тогда как в кит
стабируется **2.5.2** (каталог `lib/treectrl2.5.2/`; так же указано в `README.md`
и `docs/PLAN.md`). Числа 1236/1216/19/1 относятся к прогону набора 2.5.1.
Расхождение версий известно и не устранено: отложенная правка — привести имя
дерева тестов и его версию к 2.5.2. Измеримых последствий для этих чисел в нём
нет: единственная правка пакета в репозитории — сборочная (`DllMain` в
`tkWinTree.c` под `#ifndef STATIC_BUILD`, см. `patches/README.md`), а прочие
отличия 2.5.1 от 2.5.2 апстрима не анализировались и переоткрытия требуют,
если понадобится точность по версии.

## 10. Ловушки прогонов и инструментов сборки

Первые два пункта — разборы ложных выводов о ките и о собственном раннере;
остальные — грабли волн сборки и публикации, зафиксированные, чтобы не наступать
повторно.

- **«Регрессия scaleutil (1.14.1/1.7.1)»** в свипе GUI-тестов — эмпирически
  неверно: `scaleutil` отсутствует и в ките, и в неурезанном дереве; апстрим
  кладёт его только в `{scrollutil,tablelist}/scripts/utils/` с ленивым
  подключением. После `package require tablelist` в ките доступны scaleutil
  1.14.1, scaleutilmisc 1.7.1, `scalingPct` = 100, scrollutil 2.4, tablelist
  7.4.1. Причина заявления — дефект сравнения с baseline в самом прогоне.
- **Битый генератор Tcl-драйвера для mpexpr**: драйвер собирался конкатенацией
  double-quoted-строк PowerShell, где `$ip eval {...}` интерполировался в
  пустоту, и прогон выдавал «couldn't read file mpexpr.test» / «could not find
  interpreter» (спасала только строка с `\$ip`). Переписан на single-quoted
  here-string с плейсхолдером и циклом по обоим `.test` с `catch`; проверено
  ×2 цепочки: MPOK для обоих файлов, завершение 0. Урок: Tcl-код, генерируемый
  из PowerShell, — только single-quoted here-string.
- **Zip-спецификация docs-архива**: `.NET ZipFile.CreateFromDirectory` под
  Windows PowerShell 5.1 писал имена записей с обратными слешами, что нарушает
  APPNOTE 4.4.17 (обязан `/`) и ломает разархивацию на Linux/macOS. Упаковка
  делается per-entry (прямые слеши, записи каталогов) с самопроверкой после
  упаковки; извлечение `man.tcl`, `subst.n`, `README.md`, `demos/iwidgets/extbutton`
  из готового архива проверено.
- **PS 5.1 читает `.ps1` без BOM как ANSI**: кириллица в скрипте ломает парсер
  («Непредвиденная лексема»). Сборочные скрипты — ASCII-only, русский текст
  живёт в Markdown; по той же причине сообщения коммитов передаются файлом в
  UTF-8 без BOM (`Set-Content -Encoding UTF8` добавляет BOM, и он попадает в
  subject).
- **Markdown-спаны внутри fence-блока**: подстановка плейсхолдеров внутрь блока
  кода давала литеральные обратные кавычки в тексте (вид «`file.exe` script.tcl»
  в блоке); правило — все плейсхолдеры подставляются голыми, кавычки пишет автор
  шаблона.
- **Аннотированный тег**: `git ls-remote --tags` возвращает sha объекта тега, а
  не коммита, что давало бы ложное «moved tag»; используется peeled-ref
  `refs/tags/v<вер>^{}`. Правило: уехал локальный устаревший тег — пересоздаётся
  на HEAD; уехал удалённый — останов (тег опубликованного релиза не двигается,
  только bump версии).
- **Проверка целостности ассетов релиза**: `browser_download_url` не скачивается
  анонимно (404/reset на objects.githubusercontent.com — сетевой стек, а не
  релиз). Штатная проверка без скачивания — поле `asset.digest`
  («sha256:<hex>», префикс снимать) против локального хеша; реальное скачивание
  работает через `api.github.com/repos/…/releases/assets/<id>` с заголовком
  `Accept: application/octet-stream`.
- **Dry-run обязан быть чистым**: первая версия publish-скрипта в `-DryRun` всё
  равно создавала локальный тег, и он оставался висеть на коммите прошлого
  прогона.

## 11. Целостность урезанного staging: что и чем доказано

Staging `tcllib2.0`/`tklib0.9` внутри `kit.vfs` урезается до рантайм-только
скриптом `scripts/kit-prune.ps1`: вырезаются каталоги на любой глубине (tests,
test, test-assets, doc, docs, html, demo, demos, examples, inst, build, bench,
benches, benchmark, perf, figures, alternates, include, CVS, .svn, .git) и файлы
по расширению (порядка 60 расширений: `.test`/`.man`/`.n`/`.3`/`.md`/`.txt`/
`.html`/`.dtx`/`.pdf`/`.rtf`/`.c`/`.h`/`.cc`/`.cpp`/`.m4`/`.ac`/`.am`/`.in`/
`.csv`/`.xz`/`.gz`/`.zip`/`.tar`/`.jpg`/`.bmp`/`.tif`/`.eps`/`.gif`/`.png`/
`.inc` и другие). Защитные исключения: `pkgIndex`/`tclIndex`/`tmIndex` не
удаляются никогда, `.tcl` по расширению не удаляется, tklib `widgetl/{icons,
msgs}` сохранены. Замер эффекта на один GUI-кит: tcllib 4722→905 файлов,
tklib 759→307 (итого −3817 и −452 = −4269 файла, −32,40 МБ); размеры exe:
msvc console 23,98→10,75 МБ, msvc GUI 30,68→15,86 МБ, mingw console
24,85→11,62 МБ, mingw GUI 32,71→17,89 МБ. Более ранние записи об этом же
прогоне приводили 902/303 файла и сумму −4276: расхождение в 7 файлов
объясняется тем, что исключение по имени (`$KitLicenseNames`) спасает тексты,
которые правило `.txt` иначе срезает, — 3 в tcllib и 4 в tklib (остальные 4
из 7 и 2 из 6 имеют расширение, не запрещённое правилами, и выживали и до
него). Всё вырезанное публикуется пятым артефактом
(`tclwinkit-docs-<вер>.zip`, `scripts/build-docs-artifact.ps1`).

Расхождение в агрегате урезания фиксируется как есть: покомпонентные дельты
(3820 + 456) дают 4276 файлов, тогда как действующий сводный замер — 4269 файлов
и −32,40 МБ (см. § 8 про устаревшие цифры в `docs/ENVIRONMENT.md` и `docs/PLAN.md`,
которые цитируют 4276). Разница в 7 файлов источником не объяснена.

Доказательства, что урезание не потеряло ни одного рантайм-файла:

- `tests/tcllib-probe.tcl` перебирает все `package ifneeded` из `pkgIndex.tcl`
  образа и грузит каждый пакет (по высшей версии на имя); отказы сверяются со
  снимком неурезанного дерева (`tests/tcllib-probe.baseline.txt`,
  перегенерируется стоковым tclsh), поэтому апстримовый шум (tdom, tls, critcl,
  Trf, xml, nx, битый `nettool/nextool.tcl`, дубли версий) не маскирует и не
  имитирует регрессию. Итог по четырём китам: консоль 439 offered / 384 loaded /
  55 failed (все 55 — known-upstream, 0 новых); GUI 571 / 508 / 63
  (known-upstream, 0 новых) → PROBE OK ×4.
- Прямая A/B-проба `package require` по всем 440 пакетам, зарегистрированным в
  `pkgIndex.tcl`: урезанный kit — fail 57, неурезанный контроль — fail 62,
  «только в pruned» (то есть поломок из-за удаления файлов) — 0. Все 57 общих
  отказов — отсутствующие опциональные зависимости кита (tdom, xml, critcl, Trf,
  nx, tls, `page::plugin`/`pt::*::plugin` — плагины грузятся по требованию) и
  апстримовый баг nettool.
- Аудит `kit.vfs/lib/tcllib2.0`: остаточных `*.test` = 0, `*.man` = 0,
  `*.bench` = 0, `*.html` = 0, `*.odoc` = 0; `pkgIndex.tcl` = 131, `msgs` = 6.
- Удаление `.png`/`.gif` из tcllib безопасно: 157 png модуля `png` лежат в
  `test-assets/`, ещё 2 («physicaldimensions») — в его подкаталоге; в tklib png
  живут только в `doc/` и `figures/`. Рантайм-иконки в этих деревьях отсутствуют
  (кроме `widgetl`, который не урезался, так как `listentry.tcl` грузит их
  через `[info script]`).
- SMOKE OK ×4 (консоль/GUI × msvc/mingw), включая шесть проверок статики в
  дочерних interp: slave sqlite3, `thread::create` + sqlite3/itcl/twapi_base,
  `load {} itcl` / `load {} Itcl` в slave, safe Rl_json.
